# AGENTS.md — infinitode-dqseq Project Guide

This file helps AI quickly understand the `infinitode-dqseq` repository (a database of Infinitode 2 Top
Daily Quest Bonus Sequences): how to obtain "today's DQ", how to interpret a sequence, and how to answer
the user when asked.

## 1. Project Overview

- This repository stores the Top Bonus Sequences of the Daily Quest (DQ) for *Infinitode 2* (The Rainy Cat),
  including regular date-indexed sequences and all-time sequences found across submittable date seeds.
- Data is generated by `SeqUniverse-dqseq-20260718`, stored as plain text. **Do NOT modify any files under `data/`.**
- The repository is published on GitHub and the Infinitode Chinese community only. Using the sequences
  does not violate official rules (see `guide/Compliance.md`); in competitive online play you must disclose
  the use of this database, and the project must not be used for cheating (see LICENSE).

- DQ levels: DQ1, DQ3, DQ3L, DQ4, DQ5, DQ7, DQ8, DQ9, DQ10, DQ11, DQ12 (no DQ2/DQ6).
- Data files are pre-generated per (level × date); the repository often already contains files for future
  dates, while `DQ.json` only records date mappings confirmed up to the latest update.

## 3. How to Obtain "Today's DQ"

**Step 1: Call the official API** (the only reliable source; do NOT derive the DQ from the local clock):

```
POST https://infinitode.prineside.com/?m=api&a=getDailyQuestInfo&v=282
```

- API doc: https://app.apifox.com/link/project/7305272/apis/api-418782144 (API ID: 418782144)
- No request body; keep `v=282` as-is (version number).
- PowerShell example:
  ```powershell
  $j = Invoke-RestMethod "https://infinitode.prineside.com/?m=api&a=getDailyQuestInfo&v=282" -Method Post
  $j.data.date          # current DQ date, e.g. "2026-08-29"
  $j.data.daily_quest   # current DQ level number (string), e.g. "11" → DQ11
  $j.data.end_timestamp # unix seconds when the current DQ ends; the next DQ starts at this time
  ```
- Other response fields: `data_hash`, `min_build`, leaderboard prizes `prize_first_place` /
  `prize_second_place` / `prize_third_place` / `prize_top_3_percent`, etc. (item names observed:
  GREEN_PAPER, LUCKY_SHOT_TOKEN, CASE, SKILL_POINT, ...).

**Key points (empirically verified)**:

- DQ rotates on **UTC** dates: the DQ dated `D` runs from `D` 00:00:00 UTC until `end_timestamp`
  (= `D+1` 00:00:00 UTC).
- **`data.date` is a UTC date.** For users in non-UTC time zones, "local today" may still be the
  *previous* DQ date. Example (UTC+8): at 2026-08-30 01:00 local (= 2026-08-29 17:00 UTC) the API
  returns `date=2026-08-29, daily_quest=11`, which is correct — the DQ dated 2026-08-29 is still
  active until `end_timestamp` (= 2026-08-30 00:00 UTC = 08:00 local for UTC+8). Never substitute
  the user's local date for `data.date`; build the file path from the API value.
- The authoritative values are the API's `data.date` and `data.daily_quest`; **never** compute them
  from local time/offset.
- To decide which DQ is active, compare `end_timestamp` with the current UTC time. If
  `end_timestamp` is already in the past, a new DQ should have started; the API may briefly lag
  (~1-2 minutes), so retry once if the result looks stale.

**Step 2: Locate the data file**:

```
data/<lang>/DQ<level>/<year>/<month>/DQ<level>_<year>_<month>_<day>.txt
# e.g. data/zh_CN/DQ11/2026/08/DQ11_2026_08_29.txt
```

- `<lang>` = `en_US` or `zh_CN`; month and day are zero-padded to 2 digits.
- Build the path directly from the date and level obtained in step 1; `DQ.json` / `Dailyquestsheet` are
  only for cross-checking historical dates.
- If the file does not exist, the data for that date has not been generated/released yet: tell the user
  clearly "data for this date is not published yet" and do NOT fabricate a sequence.

## 4. Data File Format (details: guide/Rawdata.md)

Each line is one sequence record, tab-separated; the first line of every file is a header line
(whose first column is `0`), and data lines start from line 2. Records are ordered from strongest
to weakest (earlier lines are generally stronger):

| Position in line | Header | Meaning |
|---|---|---|
| 1 | `0` | Row number, starting at 1 |
| 2 | `Index` | Arabic-numeral encoding, grouped by spaces every 5 picks (e.g. `16344 31313`); 10 picks in total |
| 3 | `Bounty` (DQ8 only) | number = previous bounty stage to upgrade at before following this sequence |
| 4 | `*` | Category Optimal: among sequences sharing the same primary bonus, `*` marks the optimal one for that class (a sequence is not optimal when its main bonus is strictly inferior to another sequence's main bonus) |
| 5 | `Score` | the 249 model: every 100 points doubles damage, `y = 100·log2(x)` |
| 6 | `Summary` | abbreviated summary: core type + main bonuses with their levels (e.g. `DCR|4VULN|2DMG` in en_US, `橙4易伤2伤害` in zh_CN) |
| 7 | `Detail` | rewards obtained per stage; the leading digit(s) are stage numbers (hexadecimal: 1-9 and a=10), e.g. `4789易伤` = VULN obtained at stages 4, 7, 8, 9 |

Note: non-DQ8 files have no `Bounty` column, so `*` / `Score` / `Summary` / `Detail` shift one
position left (positions 3-6).

**Sequence decoding rules (the most commonly asked topic)**:

- Without MoreBonusVariantsNextTime (MBVNT): 1/2/3 = first/second/third option; if that stage is
  rerolled (Reroll), 4/5/6 = first/second/third option after the reroll.
- After picking MBVNT at a stage, every following stage has 4 options: 1/2/3/4 = the four options;
  after a reroll they are 5/6/7/8.
- Example: `16344 31313` → stage 1 pick option 1; stage 2 pick option 6 (= third option after a reroll);
  stage 3 pick option 3; ...

**Abbreviations**: see `guide/Abbreviation.md` for the full table (English abbreviation ↔ original term ↔
Chinese abbreviation), e.g. RCR=AddRandomCoreTile(核), ACR=ALPHACore(紫), DCR=DELTACore(橙), DMG=TowersDamage(伤害),
ASPD=TowersAttackSpeed(攻速), VULN=ExtraDamagePerBuff(易伤), CDMG=CriticalDamage(暴击), DUR=DebuffsLastLonger(时间),
LIT=LightningStrikeOnTowerLevelUp(雷电), AART=AllAbilitiesForRandomTower(全技能), TLV=GV_TowersMaxExpLevel(等级),
BPWR=IncreaseSelectedBonusesPower(序列升级), MBVNT=MoreBonusVariantsNextTime(加一).
The zh↔en mapping list in `build_rules()` of `tools/convert.py` is the authoritative bidirectional table.

**DQ8-specific note**: the `Bounty` column gives the *previous* bounty stage to upgrade at. Complete the
previous stage's selections (including rerolls) before upgrading the core bounty, and do NOT trigger the
next stage's kill conditions early; otherwise the new selections / interface resets will be affected by
the upgraded bounty stage.

## 5. All-Time Sequence Data

All-time sequence files contain the strongest sequences found by SeqUniverse across the complete range of
submittable date seeds within one minimum positive period of the date-seed cycle. They are not official DQ
history and must not be used to infer the current DQ or the DQ for a historical server date.

- File path: `data/Alltime/<lang>/DQ<level>.txt`, e.g. `data/Alltime/en_US/DQ8.txt`.
- Each row adds `Code` and `Date` before the regular `Index` / `*` / `Score` / `Summary` / `Detail` fields.
- `Code` is a 5-character base-32 date seed matching `[0-9a-vA-VzZ]{5}`. `z` and `Z` represent `0`.
- `Date` is stored as `YYYYY_MM_DD` for column alignment; enter it in the game as `YYYYY-MM-DD`.
- `Code` and `Date` identify the same date. Example: `RA59I` corresponds to `80396_05_30`, entered as
  `80396-05-30` when setting the date directly.
- DQ8 all-time files also include the `Bounty` column as the final column.
- These sequences are for **dev mode only**. Never submit scores using these dates or otherwise affect the
  current DQ leaderboard. See `guide/Alltimeseq.md` and `guide/Compliance.md`.

When the user asks for an all-time sequence, use the requested DQ level to open the matching Alltime file
and report the strongest rows. Do not call the official API unless the request also asks which DQ is
currently active, and never present an all-time date as an official server date.

## 6. Answering Guidelines

- **Language policy**: reply in the user's language by default (Chinese user → Chinese answer). Keep the
  file itself in English; when the user asks in Chinese, use the Chinese community terms (e.g.
  橙/紫/核/伤害/易伤/攻速/加一) and annotate the English abbreviations in parentheses (e.g. 橙(DCR)).
  When the user asks in English, use the English abbreviations only.
- Standard flow for "What is today's DQ / sequence":
  1. Call the API, take `data.date` and `data.daily_quest` (retry once if necessary).
  2. Build the file path and read it; first check the header line and the first data line.
  3. Suggested answer format: date + DQ level + file path + top 3-5 sequences (Index, Sequence, `*`,
     Score, Summary), then explain the column meanings (section 4).
- When explaining a sequence, give a decode example and remind: higher Score = stronger; `*` = optimal
  within its class of identical main bonus; an absent `*` means that sequence is dominated by another
  sequence in the same class and is listed for reference only.
- If the user asks about a historical date: look up `data/DQ.json` (or `guide/Dailyquestsheet.md`), then
  locate the file as in step 2 of section 3.
- If the user asks for all-time / submittable-date sequences: read `data/Alltime/<lang>/DQ<level>.txt`,
  explain `Code` and `Date`, and include the dev-mode-only / no-leaderboard-submission warning.
- If the API is unreachable: clearly state the failure; do not guess the DQ date/level and do not
  fabricate file content.
- Minor differences between the Summary and the actual in-game output are possible depending on the data
  generation environment (see Rawdata.md) and are normal.

## 7. Quick Q&A (ready to quote)

- Q: How do I read the first sequence line of today's data? A: `1	<sequence>	<bounty?>	<*>	<score>	<summary>	<detail>`, interpret per section 4.
- Q: What are the numbers in `46622 21213`? A: For each stage, which option to pick; spaces only group picks (every 5); after a reroll add +3 (no MBVNT) or +4 (with MBVNT), see the decode rules.
- Q: What is "橙" in the summary? A: DELTA core (DCR); "紫" = ALPHA core (ACR); "核" = RCR (AddRandomCoreTile).
- Q: Why does the Bounty column show a number? A: Only DQ8 has it: the bounty upgrade stage to reach before the sequence applies; upgrade at the stage indicated by the value.
